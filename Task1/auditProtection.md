## Данные для защиты и способы их обработки

| Категория данных                         | Примеры                                                     | Рекомендуемый способ защиты                                                                                                                                                                                                                                                     |
| ---------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Персональные данные (ПДн)                | Ф.И.О., дата рождения, телефон, email, адрес, место работы. | Шифрование (Encryption):Обязательно для данных при хранении и передаче. Ключи доступа к зашифрованным данным должны строго контролироваться.                                                                                                                                    |
| Медицинская информация (Врачебная тайна) | Диагнозы, результаты анализов, история болезни, назначения. | Шифрование и строгий контроль доступа (RBAC/ABAC). Доступ к расшифрованной информации — только у лечащего врача и пациента.                                                                                                                                                     |
| Данные для аналитики (BI, ML)            | Деперсонализированная медицинская и финансовая статистика.  | Обезличивание:Перед загрузкой в озеро данных все прямые идентификаторы (Ф.И.О., точный адрес) должны быть удалены или заменены на псевдонимы. Это позволит аналитикам работать с данными без риска утечки ПДн.                                                                  |
| Данные для разработки и тестирования     | Тестовые наборы данных, копии продуктивной базы.            | Обфускация / Маскирование:Для сред разработки и тестирования следует использовать не реальные, а сгенерированные или обфусцированные (изменённые до неузнаваемости) данные. Например, «Иванов Иван» заменяется на «Тестов Тест», а номера телефонов — на случайные наборы цифр. |

## Механизм тегирования данных

Инструменты и реализация:

На уровне базы данных: Можно добавить специальное поле (например, data_tag) в таблицы или использовать нативные возможности СУБД.

**public**: Общедоступная информация.
**internal**: Внутренние данные компании, не содержащие ПДн.
**confidential-pii**: Конфиденциальные персональные данные.
**confidential-medical**: Врачебная тайна, требует максимального уровня защиты.
**restricted-financial**: Финансовая информация, доступная ограниченному кругу лиц.

## Инструменты и меры для обеспечения конфиденциальности

| Область              | Инструменты и меры                                                                                                                                                                                                                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Хранение данных      | -СУБД:Переход от Excel-файлов к реляционной базе данных (PostgreSQL) для хранения структурированных данных (пациенты, записи, платежи). -Data Lake/DWH:Для аналитических задач (BI, ML) создать озеро данных на базе ClickHouse или S3-совместимого хранилища.                                                        |
| Контроль доступа     | -IAM (Identity and Access Management):Внедрение централизованной системы управления доступом.Использовать Keycloak для аутентификации и авторизации пользователей во всех системах (портал, CRM). -RBAC/ABAC:Настройка ролевой (RBAC) или атрибутной (ABAC) модели доступа.                                           |
| Шифрование           | - Использование TLS для шифрования всего трафика между клиентами (браузер, мобильное приложение) и серверами, а также между микросервисами. Применение прозрачного шифрования на уровне СУБД (TDE - Transparent Data Encryption) или на уровне приложения.                                                            |
| Сетевая безопасность | -API Gateway:Весь трафик к бэкенд-сервисам должен идти через API Gateway . Он будет отвечать за TLS, аутентификацию, авторизацию и rate limiting. -Сегментация сети:Размещение баз данных с конфиденциальной информацией в изолированном сетевом сегменте, недоступном напрямую из внешней сети.                      |
| Аудит и мониторинг   | -Логирование:Все операции с чувствительными данными должны логироваться. Логи должны содержать информацию: кто, когда, какие данные и с какой целью запрашивал. -Сбор логов в единую систему (например,Elastic Stack) и настройка алертов на подозрительную активность (например, попытка массового экспорта данных). |
